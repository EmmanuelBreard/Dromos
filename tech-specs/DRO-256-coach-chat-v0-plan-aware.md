# DRO-256 — Coach Chat V0 (Plan-Aware Advisory)

**Overall Progress:** `100%` 🟩 SHIPPED 2026-05-03

## TLDR
Re-scope the dormant DRO-149 chat into a **plan-aware advisory coach**, gated to `ebreard4@gmail.com`. The athlete asks questions about today's workout, pacing, post-session feedback, and plan rationale — the coach answers using their own profile + plan + recent execution context, streamed token-by-token. **No plan modification in V0.** Re-uses the existing `chat-adjust` edge function, `chat_messages` table, and iOS chat surface; rewrites the prompt, replaces JSON parsing with streaming, swaps the iOS transport from `client.functions.invoke()` to `URLSession + SSE`.

## Critical Decisions

- **Re-use `chat-adjust` edge function name** (not a new one) — the existing chat infra is dormant but correct in shape; renaming is churn.
- **New prompt file `ai/prompts/coach-chat-v0.txt`** (not modify `adjust-step1-v0.txt`). Old prompt was a constraint-detection JSON classifier; new prompt is a conversational coach. Different beast — keep them separate so we can A/B if needed and don't lose the old reference.
- **System/user message split for caching from day one** — the stable persona + length rules go in the system message; the dynamic athlete + plan context goes in the first user message. Aligns with DRO-255 caching pattern. ~70% of input tokens become cacheable.
- **No `status` / `constraint_summary` in V0 responses** — pure conversational text. Columns stay in `chat_messages` (NULL for V0) for V1 forward-compat.
- **SSE passthrough, not OpenAI client** in the edge function — stream the OpenAI response body directly through to the client; accumulate text server-side in a `TransformStream` so we can persist the full message on completion. Simpler than parsing chunks twice.
- **iOS `URLSession.bytes(for:)` for SSE consumption** (iOS 15+, available). Avoids pulling in a third-party SSE library.
- **Manual JWT refresh before opening SSE** — `client.auth.session` triggers Supabase SDK's silent refresh; we read the resulting `accessToken` and put it in the `Authorization` header on the manual `URLRequest`. No fancy token-mid-stream refresh — if the stream errors mid-flight, user retries.
- **Phase 1 IS the PoC** — prompt validation runs end-to-end via a local Node test rig **before any iOS or streaming work**. If prompt quality fails the qualitative bar, we re-iterate the prompt only — sunk cost on edge function/iOS streaming is zero.
- **Allowlist enforced server-side AND client-side** — defense in depth. Tab is hidden behind `currentUserEmail == "ebreard4@gmail.com"`; edge function rejects all other users with 403.
- **`recent_completed` context block MUST include lap-level Strava data** (joined through `strava_activity_laps`), not just the `feedback` text from `plan_sessions`. Phase 1 validation showed that without lap data, the model either gave generic post-session feedback or fabricated HR/power numbers. With lap data (HR per lap, max HR, speed), the model gives transparent data-backed reads and acknowledges missing power data instead of inventing it.
- **Gear/equipment opinions are in-scope** for the coach (not redirected) — Phase 1 user feedback. Updated the off-topic rule in the prompt accordingly.
